# HyperKart — 技術設計書

Three.js 一枚で走るカートレーサー。素材ファイルを持たず、**地形・テクスチャ・モデル・音のすべてを実行時に生成**する。
外部アセットは `three` のみ。

- 実装 21,709 行（`src/`、30 モジュール）
- 検証ツール 14 本（`tools/`）
- コミット 55 本

---

## 2. 設計の柱

### 2.1 シミュレーションは決定論的である

固定 120Hz。乱数はすべて種付き（`makeRng`）。同じ入力からは同じレースが出る。

これは思想ではなく**測定の前提**である。キャプチャが再現しなければ、視覚的な変更が改善なのか偶然なのか永久に分からない。本プロジェクトの検証方法は全部ここに乗っている。

### 2.2 track 空間で考える

シェルもカートも、自由な 3D ではなく**弧長 `s` と横方向 `lateral`** で進む。バンクした登りのコーナーを素直に追従でき、剛体に補正力をかけ続ける必要がない。

`Track.sampleGround(s, lateral)` が正典で、路面高・幅・曲率・接線・法線・路面種別・壁位置を返す。**メッシュ生成も物理も同じ関数を呼ぶ** — 描画面と当たり面がずれれば、カートは沈むか浮く。

### 2.3 素材を持たない

テクスチャは `ProcTex` が canvas に描き、モデルは `KartModel`/`SceneryKit` がコードで組み、音は `AudioEngine` が Web Audio で合成する。ダウンロードは three だけ。

代償は「実行時コスト」ではなく**検証の難しさ**である。生成物は目で見るまで存在が確認できない。だから `tools/` がある。

### 2.4 観測は世界を変えない

`window.__hk` はハーネス用の制御面だが、シミュレーションの意味は変えない。`shot=1` はループを止めて時計をハーネスに渡すだけで、物理は同じコードを通る。

## 3. レンダリング

**線形ワークフロー。** シーンは half-float ターゲットに描かれ、トーンマッピングは出力パスだけで起きる（`PostFX`）。したがってマテリアルが書くのは *linear scene-referred* 値である。露出は空から実測され、テーマが手で決めるものではない。

**影は単一の高解像度シャドウマップ**を、プレイヤーを追う箱にぴったり合わせる。カートカメラは活動範囲が狭いので、600m にカスケードを3枚伸ばすより、124m の箱に細かいテクセル（2048 マップで 6.1cm）を敷くほうが接地影が読める。VSM は証拠をもって却下した（`ab6f5a5`）。

**適応解像度。** `pixelRatio` をフレーム時間に合わせて動かす。60fps は解像度で買っている（実測 0.9）。

**発光路面の跳ね返り。** `emissiveIntensity 1.35` の虹路面は、半球光の `groundColor` を路面色相で駆動し、さらに**真下から上向きの指向光**を1つ足して表現する。半球光の下半分は下向き法線にしか届かず、カートにはほとんど当たらないため（実測で 4% しか動かなかった）。

## 4. 物理と AI

**`ctrl.steer` は方向ではなくヨー角の指令である。** カートはこれを `yaw` に加算し、AI は `desiredYaw - yaw` として生成する。人間の入力だけが「＋＝物理的に右」であり、その変換は `Input.js` の一箇所だけで行う。

**ドリフトは操舵モードではなく固定回転率**である。`baseRate + steerRange * stick` で回り、コーナーが要求する角度とは無関係に回る。AI はこのモデルを**逆に解いて**、ラインが要求するヨー角速度から必要なスティック量を求める（`AIDriver`）。

**横滑り**はコーナーの外へ働く。`lateralVel` は `lateral` と `g.right` と同じフレームを共有し、その正方向はカートの左である（回路の横軸は前向きカメラの左に走る — `cc78357` で計測により発見）。

**壁**は路肩 6.5m の外にあり、カート中心が `wallLateral - kartRadius` を超えると噛む。正面度で速度損失とドリフト解除を決め、浅い角度は「こすり」として平行に矯正する。

**虚空トラック**（rainbowSkyway）には壁がない。地面はカート半径 1.15m だけ路肩へ張り出しており、それを超えると落ちる。

## 5. 音声

サウンドファイルは無い。すべて Web Audio で合成する。

- **エンジン**：7セント離調したノコギリ2本＋サイン1本を、負荷追従ローパスへ。**5速ギア**で音程は各段を登り切ると下に戻る。耳は絶対的な音程よりこの「戻り」を加速として読む。
- **タイヤ**：帯域ノイズをドリフト・横滑り・路面ラフネスで開く。12台が共有ノイズ表を別オフセットで読む（同位相だと櫛形フィルタのかかった1音に合算される）。
- **風・環境・音楽ベッド**。
- **イベント 24 種**の一発音。
- 他車はパン＋距離減衰。**自車のエンジンはパンしない**（自分のエンジンは横ではなく周囲にある）。
- マスター終段は tanh ウェーブシェイパ。合計が構造的に ±1 を超えない。

`AudioUtil` は文脈非依存に書かれており、同じ合成コードが `OfflineAudioContext` でも走る。**それが、聴かずに音を検証する唯一の方法である**（§6）。

ミュートは AudioContext を suspend する。無音でも動くコンテキストはタブを「音声再生中」にし続けるため。

## 6. 検証ハーネス

| ツール | 役割 |
|---|---|
| `shot.mjs` | 決定論的スクリーンショット。`--t/--series/--track/--cam/--hud/--hide/--w/--h` |
| `sim.mjs` | ヘッドレスレース。12台3周が1秒未満。物理・AI・アイテムは実物 |
| `fxaudit.mjs` | エフェクトの実面積と、自車シルエットの遮蔽率 |
| `audioaudit.mjs` | `OfflineAudioContext` で音を描画して測る |
| `renderaudit.mjs` | draw call を払っているのに画面を動かさないオブジェクトの検出 |
| `imgstat.mjs` / `scenestat.mjs` / `kartinspect.mjs` / `skyprobe.mjs` / `analyze.mjs` | 個別の計測 |

**キャプチャの同一性は、そこへ至った経路に依存してはならない。** `shot.mjs` は要求時刻ごとにページを読み直す。

**`--hide` は嘘をついてはならない。** 一致ゼロは exit 4 で落ちる。何も隠さずに撮った絵は対照と同一で、レビュアーはそれを「この機能は何も描いていない」と読む。

## 7. 開発回顧録

55 コミットの実際の中身。ほとんどは「作る」ではなく「**見えていなかったものを見えるようにする**」だった。

### 7.1 計器が嘘をつく

1. **`--hide` は四回直した。** 一度目は `.visible` を書いても提示パスが毎フレーム書き戻していた。二度目は Group を隠しても three の `projectObject` が層テストの外で子を辿るので何も隠れなかった。三度目は自己検査そのものが守るべき A/B を壊していた（`frame()` が `uTime` を動かし、粒状ノイズがそれをハッシュする）。四度目は大文字小文字を区別して `beam` が `lighthouseBeam` に当たらなかった。**計器を直す作業は、一回では終わらない。**

2. **すべてのキャプチャが 133ms 遅れていた。** ハーネスは目標時刻へシークしたあと、シミュレーションを進めずに 8 フレーム提示していた。55ms の衝突フラッシュは構造的にどのキャプチャにも写り得ず、そのエフェクトは「散らばったゴミ」だけを根拠に設計され、再設計されていた。

3. **`--t 0` が指定できなかった。** settle 窓の内側の目標はシークだけがクランプされ、8フレームは必ず消費された。`--t 0` は 0.13333 に着地する。**レースゲームが最も判定される一枚**が、五回の批評すべてで到達不能だった。

4. **カウントダウンの数字は三度消えた。** 最初は `finish()` がアニメを終端に飛ばして要素ごと消していた（171×279px の最大 HUD 要素が、全キャプチャで不可視）。次に `race.time` へシークするよう直したが、それは同じ誤りの一段下だった — アニメがいるのは `now` ではなく `now - 自分の開始時刻` である。900ms のアニメが、レース時刻 0.9 以降は常に終端にクランプされていた。

5. **カメラが到着時にゼロにされていた。** `snapTo` が roll・shake・dip・FOV kick を捨てる。**五回の批評すべてが、2.7〜3.5° 起こして FOV の狭いフレームから下されていた** — カメラの傾きと速度感という、ルーブリックが判定しようとしていたものそのものが、一度もプレイヤーの見る値で見られていなかった。

6. **HUD が壁時計に依存していた三通り。** アニメの固定が `presentFrame` より前だった（`hud.update` が新しい CSS アニメを起こす）／無限アニメを巻き戻すだけで一時停止していなかった（アイテム枠のリールは `steps(2,end)` なので**ちょうど2通りの絵**になった）／刻印の無いアニメを 0 に固定していた（ITEM ラベルが点滅）。**差分の bounding box を取って要素を名指しする**方法で、三つとも特定できた。

7. **`backdrop-filter` がキャプチャの決定性を壊した。** 背景フィルタはロード直後の最初のフレームで、まだ合成されていない背景をサンプルしうる。「バッチの1回目だけ違う」という署名は、6 と同じものだった。

8. **性能計測がウォームアップを含んでいた。** 「60fps → 48fps に落ちた」は計測ミスだった。同一条件の同じビルドで 28.2 / 20.5 / 16.7 ms と出たので気づいた。6秒空けてから10点取る方式に直すと、劣化は無かった。

### 7.2 書かれていて、何もしていない

コードとして完全にもっともらしく、一切機能していなかったものが**12個**見つかった。

孤立したプリセット表 / ゼロ倍されるカメラ項が2つ / 無視されるシャドウ設定 / 使われないマージヘルパ / 存在しないシェーダチャンクに刺さった注入 / 世界の手前に描かれる星野 / 獲得不可能なチャージボーナス / 不透明度 0 で毎フレーム再描画される HUD 要素 / **リムの内側に封印された5本のスポーク** / 何も隠さない `--hide` / 最大差 7/255 の shadowBlob 12個 / 読み出しの無い `uResolution`。

9. **そして最大のもの：音響システム全体。** `AudioEngine` の docblock は「エンジン音、タイヤ、ドリフト、ブースト、衝突、アイテム、観客、音楽」を宣言していたが、音を出す二つのメソッドは**空**だった。`AudioUtil` の 205 行は**どこからも import されていなかった**。五回の批評は静止画のルーブリックなので、音は評価軸に一つも無く、誰も気づかなかった。

   → 教訓：**評価軸に無いものは、存在しなくても誰も気づかない。**

### 7.3 測り方を間違える

10. **音響監査ツールは、作った直後に二度自分を救った。** 最初の「主要周波数」はどの速度でも 32Hz を返した — ピンクノイズのベッドが低域を占めているのを測っていて、正常なエンジンを故障に見せていた。ベッドを黙らせたら、**エンジンは本当に無音だった**：カート毎バスのゲインを 0 で初期化したまま、どこも上げていなかった。置き換えたスタブと同じ欠陥で、そのまま出荷されるところだった。

11. **bounding box は遮蔽率を5倍に膨らませる。** 「ブーストが自車を隠す」は box 基準で 29.6%、シルエット基準で **5.9%** だった。カートの箱は大半がホイールの隙間である。この差だけで、邪魔でもないエフェクトを削る根拠になり得た。

12. **持続効果と一過性効果は静止画で比較できない。** ブーストの煙は捉えたどのフレームでも全力だが、衝突は 21 フレーム中 4 フレームしか全力でない。批評の「被弾が最も静か（8,961px 対 105,665px）」は、位相を測っていた。ピークで測ると衝突 89,494px 対ブースト 70,189px で、**むしろ衝突のほうが大きい**。

13. **効かない変更を commit しかけた。** キャニオンの中景に岩を撒いたが、問題の右40%は数値がまったく動かなかった（平均・標準偏差・高周波エネルギーが前後で同一）。「直した」と書いたコメントごと revert した。

### 7.4 仕様は正しく、沈黙が間違っていた

14. **アイテムボックスの取りこぼしはゼロだった。** 6レース分の接近を全部分類して、手ぶらで生きたボックスを通過した例は 0 件。判定は正しかった。間違っていたのは、取られたボックスが 0.3 秒だけ弾けたあと **2.7 秒間、路面に何も残らない**ことだった。「通り抜けたのに取れない」の 3対1 で多い原因が、フィードバックの無い側にあった。

15. **同じ沈黙が二度あった。** アイテム所持中はボックスを取れない — これはジャンルの標準で、正しい。しかし画面はそれを一言も言わなかった。

16. **操作パネルは読めなかった。** `loop.start()` がロード時に走り、最初のフレームからカウントダウンが減る。パネルを開けても3秒で発走していた。さらに「閉じ方」がカードに書いておらず、閉じるボタンも無かった。

    → **UI を足すときは「出す」だけでなく「読む時間」と「出方・引っ込め方」まで含めて初めて機能である。**

### 7.5 座標系と符号

17. **A で右、D で左に曲がっていた。** `ctrl.steer` はヨー指令であり、AI は正しく使っていた。人間の入力3系統だけが「＋＝右」で渡していた。カメラのワールド行列第0列（＝画面右軸）に変位を射影して測定し、修正前 -3.38m / 修正後 +11.45m を確認した。

18. **横滑りがコーナーの内側へ押していた。** コメントは「hard corners で車体に重みを与える」と書いてあり、内へ滑る挙動はその逆だった。

19. **虚空の縁がカートの内側に引かれていた。** 地面は路肩 +0.6m で消えるが、カート半径は 1.15m。**車体の 0.55m がまだ路面上にある状態で 60m の虚空に落ちていた。**

20. **回路の横軸は前向きカメラの左に走る。** 推論ではなく投影で見つかった（グリッド枠の角を投影すると u=0 が NDC +0.012、u=1 が -0.086）。この一件以降、符号は必ず測ってから直している。

### 7.6 通しての教訓

- **批評は診断装置であって判定者ではない。** 第5回批評の「計測器」の指摘は全部本物で全部直った。「印象」の数値はほとんど計測に耐えなかった（被弾の音量、ブーストの遮蔽、シャシーの同一性、明度幅 — 4件とも測ると違った）。
- **測定と実装は同じ速度で腐る。** 本書のツールはすべて、少なくとも一度は自分が測ろうとしたものについて嘘をついた。
- **「出ていない」ときは、まず出ているのに見えないのかを切り分ける。**
- **コメントが実装を追い越したら、それは負債ではなく虚偽である。** `AudioEngine` の docblock は 5 ラウンドのあいだ、存在しない機能を宣言し続けていた。
